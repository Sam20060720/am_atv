# 電視遙控器操作與焦點

更新：2026-11-01。這份表描述目前來源碼中的操作規則，不以編譯通過代替實際遙控操作證據。搜尋唯一流程為 `CatalogSearchScreen`，舊 `SearchScreen` 與根層搜尋 state 已移除。歌詞排版、時間與動畫不在本輪修改範圍。各候選版實際通過與未通過的路徑，見 [渲染稽核](../work/apple-tv-ui/render-audit/README.md)。

## 基本操作

| 位置 | 上／下 | 左／右 | 確認 | 返回 |
| --- | --- | --- | --- | --- |
| 全域選單 | 相鄰選項；帳號在清單上方 | 收起側欄並恢復目前 deck 的內容焦點（RTL 反向） | 其他分頁恢復其堆疊；確認目前分頁則關閉其詳情／輔助頁並回根頁垂直頂部 | 先聚焦預設 Home；已聚焦 Home 時交給系統離開；不偷換底下頁面 |
| Home／新發現卡片 | 換列，依畫面 X 位置挑選可見卡；第一列上到導航；最後一列下留原位。新發現的類型與五類排行榜直接接在同一頁 | 同列相鄰卡；第一張左到導航，末張右留原位 | 開啟歌曲、集合或藝人；來源種類決定動作 | 已向下捲動先回頁首；頁首展開全域選單 |
| 搜尋欄 | 上到導航；下結束輸入，進入建議，無建議則到目前範圍 | 未編輯時左到導航、右留原位；編輯時保留原生游標 | 開始輸入；再次確認或 IME 搜尋提交 | 先關原生輸入法；結束編輯後下一次返回展開全域選單 |
| 搜尋建議（API 有回傳時） | 上回輸入欄，下到搜尋範圍 | 相鄰建議；第一項左到導航，最後一項右留原位 | 搜尋建議詞，或開啟真正的建議資源 | 展開全域選單 |
| 搜尋範圍（目錄／資料庫） | 上回輸入欄；下到目前種類，空白查詢有資料時進入最近播放 | 切換兩個範圍的控制項；左側可回導航 | 選取範圍；未登入的資料庫入口進入登入 | 展開全域選單 |
| 搜尋種類 | 上回範圍；下進入目前種類的實際結果，等待資料時保留該意圖 | 水平切換相鄰種類；第一項左回導航，末項右留原位 | 選取種類並載入，保留在種類列 | 展開全域選單 |
| 搜尋結果 | 歌曲為垂直列表，其餘為四欄網格；第一列上回目前種類，末列下可到續頁／重試 | 相鄰網格項目；第一欄左回全域導航；最右側留原位 | 依資源種類開啟／播放 | 展開全域選單 |
| Library 分類列 | 相鄰分類；第一項上到導航，最後一項下留原位 | 左到導航；右先選取該分類，再進入其內容 | 選取分類並載入內容 | 展開全域選單，保留 Library |
| Library 封面網格 | 原生相鄰列；第一列上回分類，完整末列下留原位（有續頁除外） | 同列相鄰封面；第一欄左回分類，最右欄右留原位 | 依種類開啟 | 展開全域選單 |
| Library 歌曲列表 | 相鄰歌曲；第一首上回分類，最後一首下留原位（有續頁除外） | 左回分類；右留原位 | 播放該首並以列表作佇列 | 展開全域選單 |
| 專輯／歌單右欄 | 操作列下到歌曲；歌曲上／下換首；第一首上會揭露操作列與標題 | 歌曲左到導航；播放／隨機在操作列內切換 | 執行操作或播放歌曲 | 關閉詳情，恢復來源卡片；選單展開時先關選單 |
| Radio 曲風 | 相鄰網格列；第一列上到全域導航，末列下到續頁（若存在） | 同列相鄰曲風；第一欄左到導航，最右側留原位 | 開啟曲風的真實資源詳頁 | 關閉輔助頁，恢復原頁內容 |
| 設定 | 原生空間焦點搜尋相鄰控制列，垂直捲動揭露目標 | 各操作列、語言與快取首項左回導航；同列明確相鄰，末項右留原位；跳過不可聚焦的數值文字 | 執行控制項；明確的登入／登出才變更帳號 | 展開全域選單 |

Home 換列與水平揭露都使用穩定 lazy layout 幾何及封面投影外擴範圍。焦點動畫的即時縮放不回饋成新的捲動目標。

## 分頁切換、返回來源與轉場

側欄「確認目前分頁」與「向右收起」是不同意圖。前者關閉該分頁的 detail／auxiliary deck，等根頁重新啟用後呼叫既有 return-to-top；後者保留詳頁、捲動與來源焦點。確認其他分頁則恢復那個分頁已保留的 deck，不在離開時清空其堆疊。新發現首次進入以真實 feed 內容為首焦點，曲風／排行榜仍可由第一列向上到達，不再強制每次先落在曲風按鈕。

根分頁轉場採線性 **150ms 舊頁淡出 → 提交 destination → 150ms 新頁淡入**。提交前不先 mount 新頁，側欄標籤跟隨實際提交；沒有原先自行加入的 10dp 上下位移、190ms mount 動畫或歌詞用 easing。期間只接收一個切頁意圖，重複確認／指標選取與返回不另發舊目的地回呼。低效能模式立即提交；Now Playing 保留自己的播放器轉場。

回頂部回呼會啟動異步捲動，因此 `resetRootPending` 不在回呼前清除。Host 等真正開始 reset，且不包含 Nav 的根內容群組取得子項目焦點後才解除保護；側欄膠囊短暫取得焦點不能重啟 200ms 自動展開。沒有捲動可做時，先設定 `contentEntryPending` 再清除 reset。向右進入、明確展開側欄、新切頁、開啟 modal 或離開 Browse 都取消舊 reset 意圖。

每個分頁只保留輕量 session／browser 與 viewport 狀態，不同時組合所有畫面。Home／新發現保存垂直 LazyColumn、每個 shelf 的水平位置及真實焦點 cursor；Search 保存 query 結果、各類 grid/list 位置及資源鍵，重新建立原生輸入連線；Library 保存分類、網格／列表位置及項目鍵。Mixed detail stack 保留每次 visit，saveable key 包含分頁與 visit，避免兩個分頁的 visit `1` 撞在一起。Collection 以歌曲索引／操作來源、Artist／Resource 以穩定項目鍵重新發布目前組合的 requester；不能把指向已 dispose 節點的舊 requester 當成恢復成功。服務或帳號 connection state 改變會清理舊 session；離開的 browser `setVisible(false)` 取消請求與待處理焦點，沒有離頁背景全庫讀取。

### 原包證據與 Music 適配界線

以下定位是提供的 **Android Apple TV 影片 App 17.0.0** `tmp/appletv-js/app.js` 的零起算字元 offset，SHA-256：`0ff15786a4e1379dd765f31493e236b0892b16e7abe23a01723d8b34bb716361`。它不是 Apple Music tvOS 的原始碼。使用者三張 Music 照片支持浮動導航、音樂卡片及歌單右欄視覺，沒有錄下確認／方向／轉場時序。

| 已觀察的出貨來源 | 定位與適用範圍 |
| --- | --- |
| 目前分頁確認會 vertical reset；Right 選回 page deck | `menu.initialize` callback `1199916`；Sidebar Right `2473921` |
| 每個 tab 保有 root 與 stack | `getTabRoot/getTabStack/getDestinationForTab`，`836400–838000`；原包另有逾時清理／stack pruning，不代表保留所有畫面組合 |
| 根分頁方向 None、依序線性淡出／淡入 | `getTabTransition` `837388`；`TabTransition` `2831697`，實際 draw `2833538`／`2833668`；None=0。該呼叫傳 `fadeOutDuration=150`，出貨實作將同參數用於兩段；無參數時的名義入場預設才是 300ms |
| 頁面自己的背景隨頁面 DC 淡出；deck 的固定底色在外 | TabbedPage 使用背景 decorator `829251`；module `66888` 在 `2014025`，組合背景與內容 `2015047`；Canvas factory 將背景加在自身頁面 `343732` |
| 詳頁轉場不是一律同一種 | `_getPushTransition` `1205944`：影片 Playlist／Library／非 swipe Product 可走 `BasicTransition.crossfade`；factory `1447661` 為 300ms linear，底頁保持不透明、新頁疊入。特定評分／觀看方式資訊另走 InfoTransition；未匹配一般頁面可走 Instant `1208644` |

因此 Host 的固定底色與 Nav 在根頁淡出外，頁面選取的 BrowseBackdrop 與內容一起淡出。轉場開始不再把 BrowseBackdrop 設成 inactive，避免先清掉 ready 圖片／顏色才開始淡出；輸入與業務 browser gate 仍停用。側欄關閉的材質 capture 持續到 `onPanelVisibleChange(false)`，不在 spring 尚未結束時換底色／拆圖層。根頁 `LocalBrowseContentVisible` 在轉場中仍可供可見封面使用每幀一張的暖機額度，避免整段淡入只顯示佔位；互動、業務 browser 與動態封面仍保留切頁 gate。

影片 Product／評分頁的分類不等於 Music 專輯、歌手或 AMATV metadata 頁。這輪沒有把 300ms crossfade、swipe 縮放或 InfoTransition 任意套到所有音樂詳頁，也不宣稱當前詳頁立即替換就是 Music 原版效果；其精確對應仍未知。完整來源見 [官方證據](apple-tv-ui-evidence.md) 與 [本輪路由核對](../work/apple-tv-ui/render-audit/route-source.md)。

## 載入與資料變化

- Library 的 Right 不再開啟「上次選取」分類的網格。它先選取目前聚焦的分類，資料到達後才進入；使用者改按其他方向、確認或開啟導航會取消待處理進入，避免網路回應奪走焦點。
- Library 空白分類沒有假卡片，Right 保持在分類列；載入中可離開分類；失敗時可進入重試。重試進行中保留該焦點錨點與進度顯示，不接受重複啟動，成功後轉到第一個實際項目。
- Library 續頁按鈕在請求中保留可聚焦錨點，但停用啟動與按壓回饋。資料追加時，若焦點仍等待這個頁尾，轉到第一個新增項目；空的最終頁則回到最後一個有效項目。使用者向上、向左或返回時取消該轉移。
- 自動預取不主動改變一般項目的焦點；只有已聚焦的續頁錨點會等待替代項目，避免頁尾移動到新增一整頁之後而把使用者一起帶走。
- 搜尋路徑為輸入 → 建議 → 範圍 → 水平種類 → 結果。建議只在目錄查詢且 API 有回傳時出現；範圍上鍵直接回輸入欄。清空後目錄範圍顯示最近播放，資料庫範圍顯示輸入提示。查詢、範圍或種類變更會取消舊焦點意圖；種類 Down 等待自己的結果，空結果留在種類，失敗可進入重試。歌曲列表與其他結果網格各自保存捲動位置／項目鍵，續頁後才轉移仍在等待的焦點。
- Radio 曲風輔助頁在開啟詳頁時保留組合並停用底層焦點／載入。曲風以穩定資源鍵保存選取，返回後先揭露真正項目、重新綁定目前組合的 requester；不沿用已脫離的 lazy 子項目。載入失敗及使用者改按方向／確認／返回會清除舊進入意圖。新發現的五類排行榜與所有曲風直接使用同頁棚列的導航及獨立續頁，沒有另一個排行榜分類側欄；載入契約見[新發現外頁整合](apple-music-capabilities.md#新發現外頁整合類型與排行榜1101-整合)。
- 錯誤頁的重新載入文字與填色共享焦點進度；沒有顯示的登入按鈕不再是 Right 的目標。
- Library 的全域內容備援焦點綁定目前選取的分類，資料重載或舊項目消失時不會一律跳回「最近加入」。
- 專輯／歌單捲動中的焦點任務在離頁、開選單或轉向左／返回時取消；每次等待捲動／frame 後重新確認 active，避免舊任務改動底下頁面。設定的重設按鈕移除自己前，先把焦點交給仍存在的控制。
- 搜尋空頁仍有下一頁時繼續讀取，保留使用者等待進入該種類的意圖；Library 重試成功且最終無內容時移除重試錨點，返回原分類。確認鍵連發不重複切換搜尋編輯狀態。

## 播放器與詳頁返回

播放器保留自己的虛擬焦點區：控制列 → 進度列 → 歌詞／佇列／模式。控制列左／右移動，上到進度列；只有已準備且 SDK 允許 seek、時長已知時，進度列才可進入，左／右預覽 5 秒、確認提交、返回取消預覽。返回先取消預覽，再收起可見控制；控制隱藏時，手動歌詞先回即時位置，之後才離開播放器。歌詞仍維持原有上／下操作。佇列實際為水平 LazyRow：左／右移動卡片（RTL 鏡像），上到模式、下到可用的進度列或控制列；模式下／進度列上回到同一張已瀏覽卡片，不重設到正在播放的歌曲。位於卡片或模式區時暫停控制列的五秒自動隱藏；返回先關閉佇列並恢復原本歌詞／封面展示。確認鍵連發不重複啟動，已處理的 Back 同時消耗放開事件，沒有改動歌詞渲染函式。這些層級仍須安全的整合遙控驗證，不能用已超時隱藏控制列的畫面當作通過。

藝人頁目前只對實際 viewport 中的分類發出 ensure／more；熱門歌曲為明確的首次預載。頁首使用真實 Play 與圓形 More，不再放自行新增的圓形返回按鈕。載入中的分類保留不可啟動的狀態錨點，移入 viewport 才開始請求。重試保留焦點；離開／開選單取消續頁轉移；空的末頁回到最後有效項目。英雄區 More 與簡介展開各自保存選取鍵並重新綁定 requester，指標點擊也先記錄來源；專輯歌手關聯只顯示一份可操作文字，上／下能返回實際存在的動作。

專輯、藝人與通用 metadata／曲風／資料夾頁共用 mixed detail stack，支援專輯 → 藝人 → 專輯及 More → 詳細資訊再逐層返回。每次 visit 保存 lazy 狀態與焦點入口，離開的讀取暫停，返回後重新綁定已組合的目標；通用 metadata 欄位是可逐項閱讀的焦點區，長文字可在區內向上／下捲讀。關閉最上層詳頁後才回到輔助頁或來源卡片。這些是來源碼的返回規則，尚不代表所有組合都已實測。

## 驗證與效能界線

純邏輯／資料fixture、實際D-pad路徑、模擬器呈現與實體電視必須分開記錄；舊候選hash、janky比率及當時停止輸入的位置不描述目前狀態，已歸檔至忽略版控的`work/repo-review/20261104/archive/docs/tv-navigation.md`。

目前模擬器的timer修正已消除單次短窗的100ms級等待，但仍有個別33ms呈現間隔，不能宣稱穩定60fps或實體TV通過。來源、完整窗口及軸向／版本／冷啟動變因見[host timer紀錄](../work/parity-completion/20261103/emulator-host-timer.md)。

文件依據：[Compose 焦點群組與 lazy 容器](https://developer.android.com/develop/ui/compose/touch-input/focus/focus-group)、[FocusRequester](https://developer.android.com/develop/ui/compose/touch-input/focus/change-focus-behavior)、[焦點恢復](https://developer.android.com/develop/ui/compose/touch-input/focus/focus-restoration)。目前程式沿用顯式焦點錨點及穩定資源識別，不另外導入全 App 的焦點狀態機。

## 項目操作選單

Home／新發現／搜尋結果封面、Library 封面及歌曲列可長按確認或按 MENU 開啟實際項目操作。MENU 按下只記錄一次意圖，放開才開啟；正常確認仍維持開啟／播放動作。全域 FocusSurface 只在提供長按 callback 時使用 combinedClickable，其他控制不增加長按辨識。

操作選單採依來源錨點展開的浮層與 inline 子頁，開合及退場後執行導頁的規則見 [Apple TV 選單對照](apple-tv-context-menu.md)。More 返回使用來源控制項的穩定焦點；選單顯示時底層不接受焦點請求。它只在開啟後讀取 API 狀態與真正的藝人關聯，不按每張卡預先請求。它只提供資源種類、資料狀態與已驗能力支持的資料庫、喜好、評分、歌單及藝人操作。取消喜好、有catalog映射歌曲移出Library、歌單與資料夾管理沿用同一確認子頁；沒有相應能力時隱藏，不製造無作用的切換。資料庫寫入只在使用者明確按下操作時發送；建立／追加逾時沒有自動重試。

選單輸入的歸屬從開啟 state 寫入時立即生效，涵蓋瀏覽、設定及播放器，避免等 Dialog 視窗接管前仍能操作底下頁面。App 與 Dialog 共用按鍵交接紀錄：Back 只關該層，已攔截的確認鍵按下不能在切換視窗／進場完成後，因放開而執行另一操作。選單取得實際尺寸、視窗焦點並完成原進場動畫後，固定聚焦第一個實際項目；不等待首批讀取後改選中間的可用項目。讀取中／已完成的項目保留焦點與方向導航，但確認仍須通過該項目的可操作狀態與 fresh-key 保護。背景回應不重設焦點；關閉、失焦或換子頁期間重新檢查。硬體播放／暫停／上一首／下一首／快轉倒轉維持原有播放政策，在兩個視窗都只於放開時執行。

播放列表每頁載入，目標被選取後才核對 canEdit=true；若不可編輯，該目標移出選項並回到仍存在的焦點。更多項目載入時保留按鈕錨點，新資料就緒後轉到第一個替代項目；離開會取消該意圖。建立播放列表有實際名稱／說明輸入欄及確認按鈕，資料讀取在關閉時取消。寫入時保持結果視窗，等有界傳輸回覆後才能返回，避免一個按鍵同時開始第二次寫入。

資料庫資料夾的 More 可在真實父資料夾內建立空播放列表或子資料夾，並依已驗證能力提供改名、搬移及空資料夾刪除，沿用同一輸入與確認子頁。建立子項目、編輯與刪除權限分別判斷；明確的權限或服務拒絕只隱藏對應操作。寫入及讀回規則見 [Library API](library-api.md)。

跨tab回到保留詳頁／輔助頁時，只有真實requestFocus成功才清除進入內容的待完成意圖；首次尚未掛載時沿既有錨點重試。首頁「顯示全部」返回保留原棚標題／卡片；群組與Replay view各自保留已載資料、捲位及穩定項目身分，分頁完成不把焦點拉回首項。

Host 分別記錄每個 tab 的根內容是否已實際取得焦點。從播放器或其他分頁返回時，恢復該 tab 的實際來源控制；只有 lazy 目標尚未重建時才用該頁的內容備援，冷啟動尚未進入內容的根頁仍可從導航膠囊開始。詳頁、輔助頁與播放器返回共用 placement 後重試。指標與 accessibility 確認也會在導頁前記錄實際來源，避免返回另一張先前選過的卡片。
